⚖️ CISC vs RISC

czas/program = (czas/cykl) × (cykle/instrukcja) × (instrukcje/program)

RISC zmniejsza cykle/instrukcję. CISC zmniejsza instrukcje/program.

CISC

Complex Instruction Set Computing

  • ALU ← pamięć lub rejestry
  • Wiele trybów adresowania
  • reg1 = reg1 op reg2
  • Przetwarzanie szeregowe
  • Mało rejestrów
  • Dużo instrukcji
  • Złożona budowa
  • Większy pobór mocy
  • Większy koszt
  • Mniejsza szybkość

RISC

Reduced Instruction Set Computing

  • ALU ← tylko rejestry
  • Mało trybów adresowania
  • reg3 = reg1 op reg2
  • Przetwarzanie potokowe
  • Dużo rejestrów
  • Mało instrukcji
  • Prosta budowa
  • Mniejszy pobór mocy
  • Mniejszy koszt
  • Większa szybkość

CechaARM/MIPS (RISC)Intel x86 (CISC)

x86 wyższy pobór mocy wynika z wewnętrznego przekodowania instrukcji CISC → RISC micro-ops.

🦾 Architektura ARM

⭐ 6 podstawowych cech ARM (likely pytanie na kolosie)
  1. Load/store — jedyne instrukcje komunikujące rejestry z pamięcią (LDR/STR). ALU operuje tylko na rejestrach.
  2. Wyrównanie pamięci — słowo na adresie ×4, półsłowo ×2, bajt dowolnie.
  3. 16 rejestrów 32-bitowych (R0–R15), jednolity zestaw.
  4. Stała długość instrukcji = 32 bity → ułatwia dekodowanie i potok, kosztem gęstości kodu.
  5. Większość instrukcji wykonuje się w 1 cyklu maszynowym.
  6. Przetwarzanie potokowe — ARM7: 3-stopniowy (FE/DE/EX), ARM9: 5-stopniowy.
Kompensacja ograniczeń RISC w ARM
  • Warunkowe wykonanie instrukcji — redukuje skoki (brak kary za branch prediction)
  • Flagi CPSR aktualizowane tylko gdy potrzeba — sufiks S: ADDS R2,R1,R0
  • Barrel shifter 32-bit — wbudowany przesuwnik, dostępny dla większości instrukcji
  • Rozbudowane tryby adresowania indeksowego
  • Link register R14/LR — szybkie wywołania funkcji
  • Podsystem przerwań 2-poziomowy z przełączanymi zestawami rejestrów

🔧 Narzędzia deweloperskie

ICE — Przechwytywanie danych z magistrali (Pytanie Nr 3)

ICE (In-Circuit Emulator) podłącza się do magistrali mikrokomputera przez złącze i interfejs, umożliwiając precyzyjne monitorowanie, analizowanie i modyfikowanie przepływu danych.

6-krokowy proces:

  1. Podłączenie — fizyczne podłączenie emulatora do magistrali przez złącze i interfejs
  2. Przechwytywanie danych — emulator monitoruje sygnały; linia danych = dane, adresowa = adres docelowy/źródłowy, kontrolna = operacje
  3. Analiza danych — sprawdzenie poprawności, diagnoza błędów, monitorowanie transferów
  4. Modyfikowanie danych — emulator może wstrzykiwać zmiany w danych lub na adresach/sygnałach kontrolnych
  5. Sterowanie przerwaniami — emulator zarządza sygnałami przenoszeń, symuluje zdarzenia
  6. Rejestrowanie danych — zapisuje wartości danych, adresy i sygnały kontrolne do późniejszej analizy
JTAG — Interfejs debugowania (Pytanie Nr 4b)

Standard IEEE 1149.1 — interfejs do komunikacji z emulatorem wewnątrz-układowym.

Sygnały TAP controller:

  • TMS — Test Mode Select (wybór trybu)
  • TDI — Test Data Input
  • TDO — Test Data Output
  • TCK — Test Clock (sygnał zegarowy)
  • RTCK — Return TCK (zwrotny zegar)

Sygnały reset:

  • nSRST — System Reset (aktywny niski)
  • nTRST — Test Reset (aktywny niski)

Bloki wewnątrz procesora:

  • EmbeddedICE — kontroler debugowania
  • DBGRQ — debug request
  • DBGACK — debug acknowledge
Zdalne ładowanie kodu wykonywalnego (Pytanie Nr 4)

Kod przesyłany z PC do mikrokomputera przez interfejs I/O. Program zdalnego ładowania (w ROM) zapisuje odebrany kod do RAM.

Format INTELA (Intel HEX):

Każdy rekord danych zawiera:

  • 2 znaki — długość danych
  • 4 znaki — load address
  • 2 znaki — typ danych
  • N znaków — dane
  • 2 znaki — checksum

Ostatnia linia (EOF): :00000001FF

Organizacja pamięci:

AdresCODEXDATA
0x0000–0x0FFFROM (PSEN)RAM
0x1000–0xFFFFRAMRAM

PSEN = Program Store Enable — sygnał odczytu z zewnętrznej pamięci programu (ROM).

Program załadowany przez I/O (np. port RS-232) trafia do RAM (0x1000+) i tam jest wykonywany.

Pytanie
Co to jest Load/Store Architecture w ARM?
Kliknij aby zobaczyć
Odpowiedź
Tylko instrukcje LDR i STR mogą komunikować się między rejestrami a pamięcią. ALU operuje wyłącznie na rejestrach — nie ma instrukcji, które jednocześnie czytają pamięć i wykonują operację.
Pytanie
Ile rejestrów ma ARM i jakie są specjalne?
Kliknij aby zobaczyć
Odpowiedź
16 rejestrów 32-bitowych (R0–R15). Specjalne: R13=SP (wskaźnik stosu), R14=LR (adres powrotu), R15=PC (licznik rozkazów). Łącznie 37 fizycznych (bankowalność per tryb).
Pytanie
Co dodała architektura ARMv4T?
Kliknij aby zobaczyć
Odpowiedź
Zestaw instrukcji Thumb (16-bitowy). Kod Thumb ≈ 65% rozmiaru kodu ARM, 160% wydajności vs ARM na 16-bitowej pamięci.
Pytanie
Czym różni się Harvard od von Neumanna?
Kliknij aby zobaczyć
Odpowiedź
Harvard: oddzielne przestrzenie adresowe dla programu i danych → jednoczesny dostęp, różne instrukcje. Von Neumann: wspólna przestrzeń → te same instrukcje, brak jednoczesnego dostępu. ARM używa von Neumanna.
Pytanie
Jakie są główne ulepszenia Thumb-2 vs Thumb?
Kliknij aby zobaczyć
Odpowiedź
1. Dodane 32-bit instrukcje (DSP, wyjątki, koprocesory, wydajność). 2. Instrukcja IT (If-Then): warunkowe wykonanie 1–4 instrukcji. 3. CBZ/CBNZ: porównanie z zerem i skok w 1 instrukcji.
Pytanie
Wypisz 6 rodzin procesorów ARM z zastosowaniami
Kliknij aby zobaczyć
Odpowiedź
Cortex-M: MCU/IoT. Cortex-R: systemy czasu rzeczywistego. Cortex-A: OS/aplikacje. Neoverse: infrastruktura chmura/edge. SecurCore: bezpieczeństwo fizyczne. Ethos: ML inference.
Pytanie
Co to jest ICE i jakie ma zastosowanie?
Kliknij aby zobaczyć
Odpowiedź
In-Circuit Emulator — podłącza się do magistrali systemu wbudowanego. Pozwala: przechwytywać, analizować, modyfikować dane na magistrali, sterować transferami i rejestrować ruch. Niezastąpiony przy debugowaniu systemów embedded.
Pytanie
Podaj równanie czasu wykonania programu
Kliknij aby zobaczyć
Odpowiedź
czas/program = (czas/cykl) × (cykle/instrukcja) × (instrukcje/program). RISC zmniejsza cykle/instrukcję, CISC zmniejsza instrukcje/program.
Pytanie
Jakie sygnały ma interfejs JTAG?
Kliknij aby zobaczyć
Odpowiedź
TMS (wybór trybu), TDI (dane wejście), TDO (dane wyjście), TCK (zegar), RTCK (zwrotny zegar), nSRST (reset systemu), nTRST (reset test). TAP controller zarządza komunikacją.
Pytanie
Porównaj pobór mocy ARM vs x86
Kliknij aby zobaczyć
Odpowiedź

Pytanie
Podaj 5 kroków wejścia ARM w obsługę wyjątku
Kliknij aby zobaczyć
Odpowiedź
1. PC → LR. 2. CPSR → SPSR nowego trybu. 3. Ustaw tryb wyjątku w CPSR. 4. Wyłącz przerwania niższego priorytetu. 5. Załaduj wektor wyjątku do PC.
Pytanie
Co to format INTELA (Intel HEX)?
Kliknij aby zobaczyć
Odpowiedź
Format transmisji kodu wykonywalnego. Każdy rekord: 2 znaki długość | 4 znaki adres | 2 znaki typ | N dane | 2 checksum. Ostatnia linia EOF: :00000001FF.
Pytanie
Co to jest potok (pipeline) i ile stopni ma ARM7 vs ARM9?
Kliknij aby zobaczyć
Odpowiedź
Pipeline = nakładkowe wykonanie faz różnych instrukcji jednocześnie. ARM7: 3-stopniowy (Fetch/Decode/Execute). ARM9: 5-stopniowy (dodaje Memory Access i Write-Back). Proste instrukcje: 3× wydajność vs serial.
Pytanie
Czym różni się tryb Thumb od ARM w kontekście rejestrów?
Kliknij aby zobaczyć
Odpowiedź
Thumb: standardowo dostępne tylko R0–R7 (dolne rejestry). R8–R15 (górne) tylko przez specjalne warianty MOV/CMP/ADD. Brak pre/post-indeksacji w adresowaniu pamięci. Instrukcje warunkowe tylko skoki (brak IT jak w Thumb-2).
